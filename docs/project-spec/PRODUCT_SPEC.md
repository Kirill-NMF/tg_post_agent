# Product Spec: TG Audio To Post Agent

Дата: 2026-08-11

## Цель

Сделать личного Telegram-бота, который превращает голосовые сообщения и аудиофайлы в готовые Telegram-посты.

Основной MVP-сценарий:

```text
ГС / аудиофайл -> Whisper-транскрипт -> план разбивки -> rewrite -> чат-редактирование -> Telegram-оформление -> финальный пост + .txt
```

Проект не является массовым SaaS. Это небольшой инструмент для одного владельца и нескольких доверенных пользователей.

## Пользователи и доступ

- Пользователи: владелец и несколько тестовых участников.
- Доступ: только по разрешенным Telegram ID.
- Нет web-кабинета, регистрации, ролей и публичного onboarding.
- Все пользователи работают в едином стиле и общем наборе режимов.
- Список разрешенных Telegram ID хранится в env/config.

## Scope MVP

Входит в MVP:

- Telegram-бот.
- Прием voice/audio/document-аудио.
- Транскрипция через Whisper.
- Хранение транскрипта и истории проекта.
- Предложение разбивки на 1/2/3 поста.
- Выбор режима рерайта:
  - `Почистить`
  - `Сделать пост`
- Генерация черновика по одному посту за раз.
- Редактирование черновика голосом или текстом.
- Оформление в одном из двух стилей:
  - `Option 1` - простой Telegram.
  - `Option 2` - emoji formatting по референсам.
- Финальная выдача Telegram-сообщением и `.txt` файлом.
- Последовательная работа с серией постов через кнопку `Делать следующий пост`.
- Удаление аудио после завершения проекта.

Не входит в MVP:

- Zoom-созвоны как отдельный режим.
- Статьи, инструкции, конспекты, презентации.
- Стилизация под автора или корпус текстов.
- Mini app для возврата к старым проектам.
- Автопубликация в канал.
- Кастомные Telegram Premium emoji.
- S3, Redis, BullMQ, web-админка.

## Основные понятия

### Project

Проект - это отдельный текст/пост или серия постов, созданная из одного исходного аудио.

Новый project начинается только через `/start`.

Если project активен, любое новое voice/audio/text сообщение считается правкой к текущему экрану или текущему черновику.

### Post In Series

Если выбрана разбивка на 2-3 поста, бот работает последовательно:

```text
Пост 1 -> редактирование -> оформление -> финал -> Делать следующий пост -> Пост 2 -> ...
```

Если пользователь нажимает `/start`, текущая серия прекращается, старый активный поток сбрасывается, начинается новый project.

### Voice-First Editing

Основной способ правок - голосом. Текстовые правки тоже разрешены.

Голосовые правки транскрибируются через Whisper, аудио правки не хранится постоянно. В истории проекта сохраняется текст правки.

## User Flow

### 1. Start

Пользователь отправляет:

```text
/start
```

Бот:

- создает новый project;
- сбрасывает предыдущий активный поток этого пользователя;
- просит отправить ГС или аудиофайл.

### 2. Audio Intake

Пользователь отправляет voice/audio/document-аудио.

Бот:

- скачивает аудио во временное хранилище;
- при необходимости нормализует/режет файл через ffmpeg;
- запускает Whisper;
- сохраняет транскрипт;
- не показывает транскрипт пользователю;
- переходит к планированию разбивки.

### 3. Planning

Бот показывает варианты разбивки:

- `Взять 1 пост`
- `Взять 2 поста`
- `Взять 3 поста`

Для каждого варианта бот кратко показывает:

- тему;
- угол подачи;
- что войдет в пост или серию;
- если серия, тему каждого поста.

Пользователь может:

- выбрать вариант кнопкой;
- отправить голосовую или текстовую правку.

Примеры правок:

- "Сделай два поста: первый про проблему, второй про решение."
- "Оставь только тему про Avito."
- "Первый вариант норм, но убери технические детали."

После правки бот заново показывает обновленные варианты разбивки.

### 4. Rewrite Mode

После выбора разбивки бот просит выбрать режим:

- `Почистить`
- `Сделать пост`

`Почистить`:

- сохранять все слова и весь смысл исходного текста слово в слово; ничего не сокращать, не выбрасывать и не обобщать;
- разрешены только пунктуация, заглавные буквы, безошибочно распознаваемые ASR-ошибки и читаемое деление на абзацы;
- не добавлять заголовок, CTA, хэштеги, списки, редакторские метки или Telegram-постовую структуру;
- не использовать план или редакторские метаданные для изменения исходной расшифровки.

`Сделать пост`:

- собрать полноценный читаемый Telegram-пост;
- улучшить лексику, структуру и подачу;
- сохранить главную мысль и позицию автора;
- не превращать текст в сухую статью.

### 5. Draft Editing

Бот генерирует черновик текущего поста.

Черновик сразу включает:

- заголовок;
- основной текст;
- CTA/вопрос, если уместно.

На этом этапе нет отдельных экранов заголовка или CTA. Все редактируется в общем чате.

Под черновиком есть кнопка:

- `Оформить`

Пользователь может отправлять голосовые или текстовые правки.

Примеры:

- "Сделай заголовок спокойнее."
- "Убери CTA."
- "Второй абзац слишком канцелярский, перепиши проще."
- "Верни черновик целиком."
- "Дай еще вариант в более живом стиле."

После каждой правки бот:

- сохраняет правку в истории;
- обновляет черновик;
- показывает обновленный черновик;
- снова показывает кнопку `Оформить`.

### 6. Format Choice

После нажатия `Оформить` бот предлагает:

- `Option 1`
- `Option 2`

`Option 1`:

- простой Telegram;
- читабельные абзацы;
- аккуратное выделение;
- без плотной emoji-стилистики.

`Option 2`:

- emoji formatting по референсам;
- визуальная структура;
- эмоджи как маркеры;
- стиль ближе к сохраненным примерам.

### 7. Formatting

Stage 3 оформляет текст.

Правило Stage 3:

```text
Не менять слова, формулировки и смысл. Только Telegram-оформление.
```

Разрешено:

- добавлять переносы строк;
- делать абзацы;
- добавлять Telegram markdown;
- добавлять emoji;
- оформлять списки.

Запрещено:

- переписывать предложения;
- менять лексику;
- добавлять новые мысли;
- убирать важные фрагменты;
- менять тональность.

После оформления бот показывает результат.

Пользователь может:

- принять финал;
- отправить голосовую/текстовую правку.

Если правка относится к словам/смыслу, бот возвращается к `draft_editing`, обновляет черновик и затем снова предлагает `Оформить`.

Если правка относится только к оформлению, бот остается в formatting flow.

### 8. Final

Бот отправляет:

- финальный пост Telegram-сообщением;
- `.txt` файл с тем же текстом.

Если выбранная разбивка содержит следующий пост, бот показывает кнопку:

- `Делать следующий пост`

Если пользователь нажимает кнопку, бот переходит к следующему посту серии.

Если пользователь нажимает `/start`, серия завершается без дополнительного подтверждения и начинается новый project.

## States

Минимальная state machine:

```text
idle
awaiting_audio
transcribing
planning
rewrite_mode
draft_generating
draft_editing
format_choice
formatting
formatted_editing
done
```

### State Semantics

- `idle` - нет активного project.
- `awaiting_audio` - project создан, бот ждет исходное аудио.
- `transcribing` - аудио скачивается, нормализуется и транскрибируется.
- `planning` - бот предлагает или уточняет разбивку.
- `rewrite_mode` - пользователь выбирает `Почистить` или `Сделать пост`.
- `draft_generating` - Stage 2 создает черновик текущего поста.
- `draft_editing` - пользователь редактирует текущий черновик голосом/текстом.
- `format_choice` - пользователь выбирает Option 1 или Option 2.
- `formatting` - Stage 3 оформляет текст.
- `formatted_editing` - пользователь может править оформление или вернуть текст в draft editing.
- `done` - текущий пост завершен.

## Commands

### `/start`

- Всегда создает новый project.
- Сбрасывает активный поток пользователя.
- Без дополнительного подтверждения.

### Будущие команды

Не входят в MVP, но можно заложить:

- `/help`
- `/status`
- `/settings`

## Data Retention

Храним бессрочно:

- project metadata;
- Telegram user id;
- transcript;
- selected plan;
- rewrite mode;
- current and final drafts;
- formatting option;
- message/edit history;
- final text artifacts.

Не храним постоянно:

- исходное аудио;
- аудио голосовых правок;
- промежуточные ffmpeg chunks.

Аудиофайлы удаляются после завершения проекта. Временные файлы также чистятся при ошибках и по periodic cleanup.

## Model Responsibilities

### Stage 1: Whisper

Задача:

- принять аудио;
- вернуть точный transcript;
- поддерживать русский, английский и смешанную речь.

### Stage 2: Gemini

Задачи:

- предложить план разбивки;
- создать черновик;
- применять правки пользователя;
- работать как чат-редактор текущего project.

Состояние хранится на сервере, не только у провайдера модели.

### Stage 3: Claude Sonnet / ChatGPT

Задачи:

- оформить готовый черновик в Telegram style;
- соблюдать выбранный option;
- не менять слова и смысл.

Provider должен быть абстрагирован adapter-интерфейсом, чтобы можно было тестировать Claude и ChatGPT.

## Technical Stack

- Language: TypeScript.
- Runtime: Node.js.
- Telegram framework: grammY.
- Database: Postgres.
- ORM/migrations: Drizzle.
- Jobs: Postgres-backed jobs table + in-app worker.
- Audio normalization: ffmpeg.
- Deploy: Docker Compose на VPS.
- Containers: `app`, `postgres`.

Не использовать в MVP:

- Redis;
- BullMQ;
- S3;
- frontend;
- mini app;
- web auth.

## Acceptance Criteria

MVP считается рабочим, если:

- неавторизованный Telegram ID не может пользоваться ботом;
- `/start` создает новый project и сбрасывает предыдущий активный поток;
- бот принимает voice/audio;
- транскрипт сохраняется и не показывается пользователю;
- бот предлагает 1/2/3 варианты разбивки;
- пользователь может править план голосом и текстом;
- пользователь выбирает `Почистить` или `Сделать пост`;
- бот генерирует черновик;
- пользователь может многократно править черновик голосом и текстом;
- после каждой правки бот возвращает полный текущий черновик;
- кнопка `Оформить` переводит к выбору Option 1/Option 2;
- Stage 3 оформляет текст без смыслового рерайта;
- финал приходит сообщением и `.txt`;
- история проекта сохраняется;
- аудио удаляется после завершения проекта.

### Stage 3 Foundation Contract

The canonical accepted draft remains the sole lexical source. Formatting accepts only typed decoration operations anchored to that draft and renders them over the original text; a provider replacement body is never canonical.

- Option 1: Telegram readability only: paragraph boundaries and allowed Markdown spans, with no expressive emoji.
- Option 2: the same readability plus emoji insertions anchored to existing text.
- Both options preserve the original lexical text exactly; invalid, ambiguous, deleting, reordering, or unsupported operations fail closed to the original draft.
- Telegram Premium/custom emoji remains explicitly deferred and is a no-op in this phase.
